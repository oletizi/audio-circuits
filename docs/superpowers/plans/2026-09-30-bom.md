# Parts Lists (BOM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make bom` in a board directory derives what the board needs from its circuit, checks it against a committed, shared parts catalog and the board's committed choices, suggests buy quantities, and writes a committed shopping list (`BOM.md`); a committed researcher agent fills the catalog.

**Architecture:** Pure TypeScript under `tools/bom/`: needs derivation (footprint table, rating rules, operating-point dissipation), catalog and board-file validation, fit comparison, buy quantities, Markdown rendering, and a `bom` verb. Catalog entries live one per file in `parts/`; each board's choices in `boards/<board>/bom.json`. The researcher is a Claude Code agent definition plus committed sourcing notes.

**Tech Stack:** TypeScript on Bun; the existing canonical circuit model (`lib/model/`), ngspice operating point via `lib/sim/`; `make/board.mk`.

**Spec:** `docs/superpowers/specs/2026-09-30-bom-design.md` (approved). Its Decisions table binds this plan.

## Decisions (from the spec; binding)

- The parts list, with manufacturer part numbers and supplier links, is committed and updated over time.
- What a board needs is derived from the circuit on every run, never typed by hand.
- One shared catalog (`parts/<id>.json`); a part chosen once is reused by every board.
- One exact part per line, several supplier links, each with a use: `standard` (Mouser, Digi-Key), `bulk` (Tayda), `specialty` (stomp box parts, Antique Electronic Supply), `prototype-fast` (Amazon, only for parts not subject to counterfeiting).
- Commodity parts without a meaningful part number are entries with description and links only.
- Capacitor voltage rating required: the board's highest supply rail, rounded up to the next standard rating (6.3, 10, 16, 25, 35, 50, 63, 100, 160, 200, 250, 350, 400, 450 V).
- Resistor power required: operating-point dissipation x 2, never less than 0.25 W.
- `make bom` reports and never changes a choice.
- Research by one committed researcher agent that reads and adds to committed sourcing notes. A Mouser/Digi-Key search tool is a later, separate design.
- A panel pot is two lines: the pot (off-board) and the header (on-board). Default panel pot: 16 mm, solid shaft, board (PCB) pins - recorded in the sourcing notes.
- Buy quantity: cover = ceil(need x boards x (1 + shrinkage)); shrinkage > 0 required in both modes. Prototype (one board): a `stock` part gets the smallest stocking-pack price break covering it; other parts get the cover. Run: the cover, moved to a larger price break whenever that costs less in total.
- Prices are stale after 45 days.
- `make check` fails, for a board with `bom.json`, when `BOM.md` is stale or a chosen part no longer meets its line.

## Global Constraints

- Imports are explicit relative paths with the `.ts` extension.
- No fallbacks, no mock data outside tests; every unhandled case throws an error naming the thing, the observed state and the fix.
- Never bypass typing: no `any`, no `as Type` casts, no `@ts-ignore`.
- Files stay under 300-500 lines; split by responsibility.
- `bun test` and `bun run typecheck` pass before every commit. Commit and push after each task. No AI attribution of any kind in commit messages or PR text.
- Never put `#` inside a Bash heredoc or multi-line quoted argument; write commit messages to files and use `git commit -F`. Never use `sed` to write files.
- Work on branch `feature/transistor-preamp`. Never use `git stash` or `--no-verify`.
- Never call anything "production-ready"; no temporal project-management wording.
- `BOM.md` contains nothing that depends on today's date (so it is reproducible and `make check` can compare it); staleness is reported on the console only.

// tools/bom/types.ts
export type Physical =
  | { readonly kind: "axial-resistor"; readonly body: "0207"; readonly leadSpacingMm: number }
  | { readonly kind: "radial-electrolytic"; readonly maxDiameterMm: number; readonly leadSpacingMm: number }
  | { readonly kind: "to92"; readonly pinOrder: readonly string[] }   // e.g. ["emitter", "base", "collector"]
  | { readonly kind: "trimmer"; readonly package: "RM-065" }
  | { readonly kind: "pin-header"; readonly pins: number; readonly pitchMm: number }
  | { readonly kind: "panel-pot" }

export interface BomLine {
  readonly key: string                 // stable, human-readable; see below
  readonly placement: "on-board" | "off-board"
  readonly designators: readonly string[]   // sorted naturally (R2 before R10)
  readonly quantity: number
  readonly kind: ComponentKind
  readonly ohms?: number
  readonly farads?: number
  readonly taper?: "linear" | "log"
  readonly mpn?: string                // when the circuit names the part (e.g. 2N3904)
  readonly physical: Physical
  readonly minVolts?: number           // capacitors
  readonly minWatts?: number           // resistors
}

// tools/bom/footprints.ts
export function physicalFor(footprint: string, component: Component): Physical   // throws on an unknown footprint, naming it and this table

// tools/bom/ratings.ts
export const STANDARD_CAPACITOR_VOLTS: readonly number[]
export function requiredCapacitorVolts(highestRailVolts: number): number   // next standard rating >= rail; throws above 450
export function requiredResistorWatts(dissipationWatts: number): number    // max(0.25, 2 x dissipation)

// tools/bom/needs.ts
export function deriveNeeds(
  circuit: BoardCircuit,
  highestRailVolts: number,
  dissipation: ReadonlyMap<string, number>,   // component id -> watts; required for every resistor
): readonly BomLine[]
```

- [ ] **Step 1: Footprint table (tests first).** `physicalFor` recognises exactly: `Resistor_THT:R_Axial_DIN0207_*_P<p>mm_*` (lead spacing parsed from `P<p>mm`); `Capacitor_THT:CP_Radial_D<d>mm_P<p>mm` (both parsed); `Package_TO_SOT_THT:TO-92_Inline` (pin order from the circuit's `PIN_NUMBERS` for `bjt` in `circuits/transistor-preamp/parts.ts`: pin 1 emitter, 2 base, 3 collector - take it from the component's part `pads` or the kind's pin numbering the circuit uses; if neither states it, throw); `Potentiometer_THT:Potentiometer_Runtron_RM-065_Vertical`; `Connector_PinHeader_2.54mm:PinHeader_1x<n>_P2.54mm_Vertical`. Tests: each recognised footprint's parsed values; an unknown footprint throws naming it.
- [ ] **Step 2: Rating rules (tests first).** Tests: rail 24 -> 35; rail 9 -> 10; rail 25 -> 25; rail 500 throws; dissipation 0.01 W -> 0.25; 0.2 W -> 0.4.
- [ ] **Step 3: Move the board-circuit loader** to `tools/perfboard/board-circuit.ts`; update the guide's imports; all existing tests still pass.
- [ ] **Step 4: `deriveNeeds` (tests first).** Group components with identical requirements into one line. Line key: `<kind> <value> [<taper>] [<mpn>] <footprint name without library>`, e.g. `resistor 100K R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal`, value written with `lib/kicad/value-notation.ts`. A panel pot (`isPanelPot`) yields two lines: an off-board `panel-pot` line (ohms, taper) and an on-board `pin-header` line (3 pins). A component with no footprint, or a kind with no rule here (switch, diode, inductor, photoresistor, opamp, ic), throws naming the component and kind. A resistor missing from `dissipation` throws. Tests on a small hand-built network: grouping and quantities, keys, natural designator order, panel-pot split, capacitor `minVolts`, resistor `minWatts`, the throws.
- [ ] **Step 5:** `bun test && bun run typecheck`; commit and push.

// tools/bom/catalog.ts
export type SourceUse = "standard" | "bulk" | "specialty" | "prototype-fast"
export interface PriceBreak { readonly quantity: number; readonly unitPrice: number; readonly pack?: boolean }
export interface Source {
  readonly supplier: string; readonly url: string; readonly sku?: string
  readonly currency: string; readonly breaks: readonly PriceBreak[]   // ascending quantity, first break is the minimum order
  readonly checked: string   // YYYY-MM-DD
  readonly use: SourceUse
}
export interface Specs {
  readonly ohms?: number; readonly farads?: number; readonly tolerancePercent?: number
  readonly volts?: number; readonly watts?: number
  readonly leadSpacingMm?: number; readonly diameterMm?: number
  readonly package?: string            // "0207", "TO-92", "RM-065", "pin-header"
  readonly pinout?: readonly string[]  // TO-92 pin order as the datasheet gives it, e.g. ["emitter", "base", "collector"]
  readonly pins?: number; readonly pitchMm?: number
  readonly taper?: "linear" | "log"
}
export interface Evidence { readonly spec: keyof Specs | "mpn"; readonly url: string; readonly note: string }
export interface CatalogEntry {
  readonly id: string; readonly kind: string; readonly description: string
  readonly manufacturer?: string; readonly mpn?: string
  readonly specs: Specs; readonly evidence: readonly Evidence[]
  readonly why: string; readonly stock: boolean; readonly sources: readonly Source[]
}
export function parseCatalogEntry(json: unknown, file: string): CatalogEntry
export function loadCatalog(dir: string): ReadonlyMap<string, CatalogEntry>   // parts/*.json; id must equal the file name

// tools/bom/board-bom.ts
export type Purchasing =
  | { readonly mode: "prototype"; readonly shrinkage: number }
  | { readonly mode: "run"; readonly boards: number; readonly shrinkage: number }
export interface Extra { readonly part: string; readonly quantity: number; readonly why: string }
export interface BoardBom {
  readonly purchasing: Purchasing
  readonly lines: Readonly<Record<string, string>>   // line key -> catalog id
  readonly extras: readonly Extra[]
}
export function parseBoardBom(json: unknown, file: string): BoardBom

// tools/bom/quantity.ts
export interface BuySuggestion { readonly quantity: number; readonly unitPrice: number; readonly linePrice: number }
export function coverQuantity(need: number, purchasing: Purchasing): number
export function suggestBuy(need: number, purchasing: Purchasing, entry: CatalogEntry, source: Source): BuySuggestion
```

- [ ] **Step 1 (tests first): catalog validation.** Refuse, naming file and field: missing required fields; an `id` that differs from the file name; a spec present with no `evidence` entry naming it; `mpn` present without evidence; an unknown `use`; breaks not ascending or empty; `checked` not `YYYY-MM-DD`; `stock: true` with no source having a `pack` break.
- [ ] **Step 2 (tests first): board file validation.** Refuse: missing `purchasing`; `shrinkage` not > 0; `boards` not a positive integer in `run`; non-positive extra quantity.
- [ ] **Step 3 (tests first): quantities.** `coverQuantity(1, prototype 0.1) = 2`; `coverQuantity(10, prototype 0.1) = 11`; `coverQuantity(3, run 5 boards 0.1) = 17`. Prototype, stock part, breaks [1 @0.10, 100 @0.012 pack] -> 100 @0.012. Prototype, stock part with no pack covering the cover -> throws naming entry and supplier. Prototype, non-stock -> cover at the break price for that quantity. Run: cover 17, breaks [1 @0.50, 25 @0.30] -> 25 @0.30 (7.50 < 8.50); cover 17, breaks [1 @0.50, 100 @0.30] -> 17 @0.50. A cover below the first break's quantity buys the first break's quantity.
- [ ] **Step 4:** `bun test && bun run typecheck`; commit and push.

// tools/bom/render.ts

- [ ] **Step 1 (tests first): fit.** Per field: value equal (`ohms`, `farads`); `taper` equal; `mpn` equal when the line names one; `volts >= minVolts`; `watts >= minWatts`; axial: `package === "0207"` and `leadSpacingMm` equal; electrolytic: `diameterMm <= maxDiameterMm`, `leadSpacingMm` equal; TO-92: `package === "TO-92"` and `pinout` equal to `pinOrder`; trimmer: `package === "RM-065"`; header: `pins` and `pitchMm` equal; panel pot: value and taper only. A needed spec the entry does not state is a misfit ("not stated"), never assumed.
- [ ] **Step 2 (tests first): report.** Each category on a hand-built case; staleness counts days between `checked` and `today`, stale when > `staleDays`; `reportText` names each item with the fix (choose a part with the researcher; remove the key from bom.json; ...).
- [ ] **Step 3 (tests first): Markdown.** Title, the conditions line, sections On the board / Off the board / Extras, columns: designators, need, buy, description, manufacturer + MPN, links (one per source: `[supplier (use)](url)`), unit and line price at the suggested quantity per source, then a totals table per supplier and currency. Unchosen lines render as rows saying "not chosen". Deterministic: same input, same text; no dates other than each source's `checked`.
