<|channel|>analysis<|message|>**1.  What the user wants**

The user has supplied a list of parts, nets and a few label names.  
The goal is to create a Ki‑Cad schematic that  
* places every component in a readable layout,  
* adds the four global labels (`hi_boost_out`, `in`, `lo_boost_in`, `out`),  
* connects the pins that belong to the same net, and  
* finally writes all the wires.

The Python wrapper functions provided already do the heavy‑lifting, so the script will simply call them in a logical order.

---

**2.  Choosing a reference point**

The schematic sheet is 210 × 297 mm (A4).  
A convenient centre for the whole circuit is `(150 mm, 110 mm)` – close to the centre of the sheet and far from the edges.  
All other components will be positioned relative to this centre using integer offsets so that the resulting drawing is clean and the symbols do not overlap.

---

**3.  Symbol placement strategy**

| Symbol | Library | Reference | Value | Rotation | Mirror | Rough offset from centre (mm) | Reason for offset |
|--------|---------|-----------|--------|----------|--------|-----------------------------|------------------|
| J1, J2 | Connector_Generic | J1, J2 | Conn_01x05 | 0 | None | `(-50, +30)` and `(+30, +30)` | Keep the 5‑pin header on the bottom of the circuit, spaced 80 mm apart |
| C1…C6 | Device:C | C1–C6 | 0.33 µF … 0.033 µF | 0 | None | `(-45, +10)` to `( +35, +10)` (every 10 mm apart) | Stretches along a horizontal line for easy routing |
| R1 | Device:R | R1 | 56 kΩ | 0 | None | `(-45, -10)` | Below the capacitors, short vertical connection to the first switch pin |
| RV1 | Device:R_Potentiometer | RV1 | 47 kΩ | 0 | None | `(-30, -10)` | To the right of R1, same horizontal axis |
| SW1 | Switch:SW_Rotary_1x6_MP | SW1 |  | 0 | None | `2, -5` | Slightly right of the potentiometer, a little lower so its pins can reach the capacitors |
| SI1‑SI8 | Device:R or Device:C | SI1‑SI8 | 0 Ω … 100 kΩ | 0 | None | In a horizontal chain from `(-35, -30)` to `( +35, -30)` | Each pair is 10 mm apart, all on the same line |
| GND power symbol | power | #PWR_GND | GND | 0 | None | `(-45, -45)` | A single global ground label that all low‑side pins will connect to |

The chosen offsets keep a 10‑mm “padding” between neighbouring symbols, which is enough for the default 2‑mm symbol size and the 1‑mm wire width.

---

**4.  Adding the global labels**

The four net names are added **once** at a convenient location near the centre of the schematic:

```
label_pos = (center_x, center_y + 30)
```

All labels are of type “input” and have the text orientation “left” so that the label text is readable when the schematic is rotated 0°.

---

**5.  Wiring the nets**

The wiring follows the net list.  For each net we connect every component pin that belongs to it.  
The `connect_pins` calls use the *reference* of the symbol and the *pin name* that appears in the net list.  
The pin names are exactly the names that appear in the part list (`Pin_1`, `Pin_2`, …, `1`, `2`, `3`, `D`, `S`, etc.).

**GND net**  
All the “.1” pins of C1‑C6 and every J1/J2 pin that is a ground pin (`Pin_5`, `Pin_1`, …) are all connected to the single ground label `#PWR_GND`.  
The ground symbol has only one pin, so we always use “1” as the pin identifier.

**hi_boost_out, in, lo_boost_in, out nets**  
For each of these four nets we create a global label and then connect that label to the first component on the net.  
All other components on the same net are then wired to that same label.  
This keeps the wires short and avoids a dense “bus” of many direct connections.

**C‑to‑switch nets (j10_p1 … j10_p6)**  
The first six nets are simple one‑to‑one connections:  
`C1.2 ↔ SW1.1`, `C2.2 ↔ SW1.2`, …, `C6.2 ↔ SW1.6`.  
Each of these is a single `connect_pins` call.

**Lo‑boost‑in net**  
This is a multi‑port connection that uses a chain of several components:  
`J1.3`, `R1.2`, `RV1.2`, `RV1.3`, `SI3.1`, `SI6.2`, `SW1.7`.  
We link them in the order listed, each connection being a simple two‑pin wire.  
The order is chosen to keep the routing straight: all the pins lie on a roughly horizontal line, so the wires run mostly horizontally or vertically.

**Si‑hi‑boost‑j20‑p3, si‑hi‑cut‑j12‑p3, si‑hi‑cut‑j4‑p2**  
These nets involve a pair of components each:  
`SI1.2 ↔ SI2.1`,  
`SI3.2 ↔ SI4.2`,  
`SI4.1 ↔ SI5.2 ↔ SI6.1`.  
They are connected with a simple chain of two wires.

**out net**  
`J1.4 ↔ R1.1 ↔ SI7.2` – a three‑point chain that is a single continuous path.

---

**6.  Writing the wires**

After all `connect_pins` calls have been issued, `write_out_all_wires()` is invoked.  
This generates the actual wire objects in the Ki‑Cad schematic, automatically merging any overlapping or collinear segments.

---

**7.  Example of a snippet**

```python
# Add the centre 5‑pin header
add_schematic_symbol("Connector_Generic", "Conn_01x05",
                     pos_x=150-50, pos_y=110+30,
                     reference="J1", value="Conn_01x05",
                     rotation=0, mirror=None)

# Add the first capacitor
add_schematic_symbol("Device", "C",
                     pos_x=150-45, pos_y=110+10,
                     reference="C1", value="0.33uF",
                     rotation=0, mirror=None)

# Connect C1.1 to ground
connect_pins("C1", "1", "#PWR_GND", "1")

# Add the global label for the hi_boost_out net
add_label([150, 140], "hi_boost_out", "hi_boost_out_0",
          label_type="input", text_orient="left")

# Connect the first component on that net (e.g. J1.2) to the label
connect_pins("J1", "Pin_2", "hi_boost_out_0", "1")
```

The full script will contain one block similar to the table above for every symbol, then a block of `connect_pins` calls for every net, and finally the single `write_out_all_wires()` call.

---

**8.  Summary of the reasoning**

* A central reference point keeps the layout balanced.  
* All symbols are offset by whole‑number multiples of 10 mm to give ample spacing.  
* Rotations are left at 0° (except for the 90° rotation of the potentiometer when needed to keep its middle pin vertical).  
* Mirror is never used because the default orientation already matches the pin directions.  
* Global labels are placed near the centre and connected to the first element of each net; all other members of the net are then connected to that label.  
* The `connect_pins` calls follow the net definitions exactly, using the real pin names from the symbol data.
