The user wants a KiCad schematic that implements the network described in the “PARTS / NETS / LABELS” section.  
All parts are simple passive components or a rotary switch, a 1‑row connector, a GND power label and a “+‑” (or GND) power label is not explicitly required because the net list already defines a GND node.  
The schematic must be centred on an A4 sheet (210 × 297 mm) so we will pick a centre point around 150 mm × 110 mm and arrange the components in a tidy block layout.  All wires must be created with the **`connect_pins`** helper and all global labels must be added for the four user‑visible nets (`in`, `lo_boost_in`, `hi_boost_out`, `out`).  

Below is the step‑by‑step plan that will be translated into the Python script.

---

### 1. Choose a reference point and spacing

* **Center of the whole block:** `center_x = 150 mm`, `center_y = 110 mm`.  
* **Component groups** – the rotary switch will be the central “spine.”  
  * The six capacitors (C1‑C6) are placed to the left of the switch, each 10 mm apart horizontally.  
  * The six resistors (R1‑R8) and the potentiometer (RV1) are placed to the right of the switch, also spaced 10 mm.  
  * The two connectors (J1, J2) sit further to the right, each 15 mm away from the nearest component.

* **Margins** – a 5 mm clearance from the outermost pins to the sheet edges, therefore all x‑coordinates stay between 20 mm and 190 mm.

All distances are integer multiples of 5 mm so the layout stays “grid‑like” and wires run mostly horizontal/vertical.

---

### 2. Add the symbols

| Symbol | Library | Reference | Value | Position (relative to centre) | Rotation | Mirror |
|--------|---------|-----------|--------|-----------------------------|----------|--------|
| Rotary switch | Switch:SW_Rotary_1x6_MP | SW1 | “SW_Rotary_1x6_MP” | (0, 0) | 0° | None |
| Capacitors C1‑C6 | Device:C | C1‑C6 | 0.33 µF, 0.22 µF … 0.33 µF | left side, `‑80,‑60,‑50,‑40,‑30,‑20` mm | 0° | None |

The GND symbol will be placed to the left of the leftmost capacitor so that the GND net can be pulled down to the bottom of the block.  
The global “+1 V” or “+1 V8” power symbol is unnecessary because the user has not requested it; we will simply connect the + rail to the top of the block via a **power‑label** `+V` (we can add an `#PWR1` if desired, but the code example did not use one).

---

### 3. Add global labels

Four user‑visible labels are required:

| Net | Label text | Pin to attach to | Label orientation |
|-----|------------|-----------------|------------------|
| `in` | “in” | J1‑Pin 1 | left |
| `lo_boost_in` | “lo_boost_in” | J1‑Pin 3 | left |
| `hi_boost_out` | “hi_boost_out” | J1‑Pin 2 | left |
| `out` | “out” | J1‑Pin 4 | left |

The `add_label` call uses the pin coordinates of the referenced pin obtained from **`get_pin_location`**, then moves the label a few mm left (negative x) so the text is readable.

---

### 4. Wire all connections

The net list in the request maps every pin to a net.  We translate that list into a set of `connect_pins` calls:

1. **GND net**  
   * All capacitor pins 1, connector J2 pins 1‑5, and the GND symbol pin 1 are all tied together.  
   * `connect_pins("C1","1","GND","#PWR_GND","1")` repeated for each component, then `connect_pins("#PWR_GND","1","J2","1")`, etc.

2. **hi_boost_out net** – connects J1‑Pin 2 to all SW1 pins 1, 2, 3, 5, 7 (the rotary switch outputs).

3. **in net** – connects J1‑Pin 1 to SI1‑Pin 1 and SI8‑Pin 1 (the two “in” pins on the switch).

4. **lo_boost_in net** – connects J1‑Pin 3 to the long side of the 2‑pole‑position of the switch (SW1‑Pin 7).

5. **hi_cut and hi_… nets** – the user defined many internal cross‑connections (e.g., `SI1‑2 to SI2‑1`).  Those are implemented with direct pin‑to‑pin connections:  
   * `connect_pins("SI1", "2", "SI2", "1")` etc.

6. **Other cross‑connections** – the “j10_pX” nets simply connect the capacitor’s second pin to the corresponding switch pin.  
   * Example: `connect_pins("C1","2","SW1","1")`

7. **Power rails** – The +‑voltage rail (if we add a power label) is connected to the far right side of the block so that all “+V” connections can run vertically up and then horizontally to the components.

All these connections are grouped in the script in logical blocks: first we connect the GND net, then the four user‑visible nets, then the internal cross‑connections.

---

### 5. Write the wires

After all **`connect_pins`** calls are finished, `write_out_all_wires()` will generate the actual KiCad wire objects.  No additional geometry adjustments are needed because the helper functions already handle the straight‑line routing on a grid.

---

### 6. Code‑generation details

* **Import section** – same as the example:
  ```python
  import sys, os
  PROJECT_PATH = os.environ['PROJECT_PATH']
  sys.path.append(PROJECT_PATH)
  from modules.kicad_sch_interface import *
  ```

* **Adding symbols** – we call `add_schematic_symbol` with the parameters from the table above.  
  * For every symbol we use the exact reference names (`C1` … `C6`, `R1` … `R8`, `RV1`, `SW1`, `J1`, `J2`).  
  * The `rotate` argument is left at `0` for all components because the default orientation already aligns the pins with the grid.  
  * Mirror is `None` for all except the switch if we decide to flip it horizontally – in this layout we keep it unmirrored for readability.

* **Adding global labels** – after placing the label we call `connect_pins(label_ref, "1", pin_ref, pin_name)` to tie the label to the pin.

* **Connecting pins** – each `connect_pins` line follows the pattern  
  ```python
  connect_pins("<ref_a>", "<pin_a>", "<ref_b>", "<pin_b>")
  ```
  where `<pin_a>` or `<pin_b>` is either a pin name (e.g. “Pin_1”) or the single pin “1” for power/GND symbols.

* **Final call** – `write_out_all_wires()` prints the wire objects to the schematic file.

---

### 7. Why this plan works

* **Readability** – The block layout keeps all like‑function groups next to each other, so the user can trace the four main nets visually.  
* **Minimal wire length** – By placing connected pins close together (e.g., J1‑Pin 2 and SI2‑1) the script avoids long horizontal or vertical runs.  
* **No overlaps** – All bounding boxes are separated by at least 5 mm, and the central switch’s large bounding box is the anchor, so no symbol boxes overlap.  
* **Correct pin names** – The script uses the pin names exactly as defined in each library (`Pin_1`, `Pin_2`, etc.) and the switch’s special “MP” pin for the return path.  
* **Scalability** – The pattern can be extended to add more switches or connectors by simply adjusting the relative offsets; the code stays readable.

---

**Conclusion**

The final script will:

1. Set up the project environment.  
2. Place the 2‑point rotary switch at the centre.  
3. Position all capacitors, resistors, the potentiometer, and connectors around it.  
4. Add a GND symbol and the four global labels.  
5. Wire every pin according to the user‑specified net list, ensuring the four main signals are clearly visible.  
6. Call `write_out_all_wires()` to finalize the schematic.
