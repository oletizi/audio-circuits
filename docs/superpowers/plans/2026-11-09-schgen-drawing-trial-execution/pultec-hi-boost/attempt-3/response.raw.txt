The user has supplied a *parts list*, a set of *net names* and a set of *global labels*.  
The goal is to generate a KiCad schematic that contains every part, connects the pins that belong to the same net, and places the four global labels (`hi_boost_out`, `in`, `lo_boost_in`, `out`) on the appropriate wires.  
All components are passive (capacitors, resistors, inductors, a rotary switch and two 1‑x‑5 connectors). The schematic must be readable, with components spaced so that no bounding boxes overlap.

**2.  Overall layout strategy**  
* **Reference point** – Use the centre of the rotary switch (`SW1`) as the anchor (`center_x_1, center_y_1`).  
* **Horizontal band** – All other components are arranged in three horizontal rows (top, middle, bottom) relative to SW1.  
  * **Top row** – the “hi‑boost” side: C1–C3–C5–L4, the 4‑kΩ resistor, and the high‑side of the GND‑ground bus.  
  * **Middle row** – the “lo‑boost” side: C2–C4–C8–L2, the 2‑kΩ resistor, and the low‑side of the GND‑ground bus.  
  * **Bottom row** – the “in/out” side: C6–C7–C9–L1, the two extra resistors (R1.2, R1.3), the 470 Ω resistor, and the 1‑x‑5 connectors.  
* **Vertical offsets** –  
  * `+20 mm` upward for the top row, `0 mm` for the middle row, and `‑20 mm` for the bottom row.  
  * `+8 mm` horizontal offsets are used to keep each component roughly one‑footprint width apart.  
* **Rotations** –  
  * All capacitors, resistors and inductors are left at `0°` (or `180°` for the two resistors that are mirrored on the left side of the switch) so that their pins are vertical.  
  * The switch is placed at `270°` (rotated clockwise so its pins run horizontally, which is the natural orientation for a rotary switch in KiCad).  
  * The GND symbol is kept at `0°` because it has only one pin.

**3.  Placing the symbols**  
For each symbol the arguments to **`add_schematic_symbol`** are chosen as follows:

All offsets are integer multiples of 8 mm (horizontal) or 20 mm (vertical).  The GND symbol is offset downward so that it sits under the connectors, which is the usual visual convention for a ground bus.

**4.  Adding the global labels**  
For each net that is listed in **LABELS** we create a single global label that will be attached to one wire belonging to that net.  
* The label is placed *just next to* the pin we choose to represent the net.  
* `text_orient` is selected to keep the label readable:  
  * “right” for labels that sit on the right side of the wire, “left” for those on the left side.  
* The position is `pin‑location ± (5 mm, 0)` (or a few mm on the Y‑axis) to avoid overlapping the wire but stay close enough to be obvious.  
* The label reference is the net name appended with “_0” (e.g. `hi_boost_out_0`).  
* The label type is `input` because all these nets are driven from the connectors or the switch.

**5.  Wire connections**  
The **`connect_pins`** calls are derived from the net list.  For each net we connect every pin that belongs to that net in a chain.  The algorithm is:  

1. **Collect all pins** – For a given net, fetch every symbol‑pin pair that appears in the net description.  
2. **Create a chain** – Connect the first pin to the second, the second to the third, …, and finally the last pin back to the first if the net is closed.  
3. **Global label connection** – After the chain is built, connect the global label to the first pin of the net so the label is attached to the wire block.

The nets in the user request are large (e.g. `j15_p1` contains 3 C and 1 L pins, `hi_boost_out` contains 4 pins from two C, a L and a R).  
For such nets we simply chain them in the order listed in the net definition – this keeps the code readable and ensures all pins are electrically in the same net.

**6.  Example of a connection chain**  
For the net **`j15_p1`** (C6.1, C7.1, C9.1, L1.1):  

```
connect_pins("C6", "1", "C7", "1")   # C6.1 → C7.1
connect_pins("C7", "1", "L1", "1")   # C7.1 → L1.1
connect_pins("L1", "1", "C9", "1")   # L1.1 → C9.1
```

The three `connect_pins` statements create a single wire that runs through all four components.  The global label `lo_boost_in_0` will then be connected to the first pin, e.g.:

```
connect_pins("lo_boost_in_0", "1", "C6", "1")
```

**7.  Final step – write the wires**  
After all `connect_pins` calls, a single call to **`write_out_all_wires()`** emits the full wire data into the KiCad schematic file.  This is required by the KiCad API to commit the netlist.

**8.  Why the chosen rotations and mirroring work**  
* The switch is rotated to 270° because its 6 normally‑closed (NC) pins are horizontally aligned.  This orientation matches the typical KiCad symbol for a rotary switch and keeps the wires running straight to the surrounding components.  
* The two 47 kΩ potentiometers are mirrored (180°) on the left side of the switch to keep their wipers at the same horizontal line as the other components, simplifying the routing.  
* All other components are left unmirrored; their default orientations already expose the vertical pins, which is convenient for placing the wires horizontally between the rows.

**9.  Summary of the code flow**  
1. Import the KiCad schematic interface.  
2. Define the centre coordinates (`center_x_1`, `center_y_1`).  
3. Call `add_schematic_symbol` for every part, using the offsets and rotations described above.  
4. For each global label, obtain a pin location with `get_pin_location`, create the label with `add_label`, and connect it to the pin with `connect_pins`.  
5. For each net, chain all its pins with `connect_pins` in the order supplied.  
6. Finish with `write_out_all_wires()` to output the full schematic.
