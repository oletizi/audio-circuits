Deviations from the brief (each forced; each commented in the file)

1. No `--rm`. The brief requires reading `.State.OOMKilled` "before removal", which `--rm` makes impossible (the daemon removes the container on exit). The EXIT trap does `docker kill` + `docker rm -f` on every path, including success; every test asserts `docker ps -a --filter name=schgen-emit-` is empty afterwards. Cost: if emit.sh itself is SIGKILLed, an exited container is left behind (a running one would be left in either design).
2. `docker exec <name> cat /out/page.kicad_sch`, not `docker cp`. Measured: docker cp returned "Could not find the file /out/page.kicad_sch in container" because it cannot see a tmpfs mount. The hold-open/SIGUSR1 handshake is otherwise as specified.
3. An 8 MiB cap on the container's stdout/stderr into emitter.log, reported as LIMIT: output-bytes. Not in the brief; added because the brief's guarantee that nothing reaches the host OUT_DIR past the sheet had a hole: a `while True: print(...)` program wrote a 54 GB emitter.log in about two minutes during my RED run (deleted immediately; ~47 GB free on the disk afterwards). First attempt used `head -c`, which buffers its output and withheld the ready marker, deadlocking success runs; replaced by cap_stream.py (unbuffered os.read/os.write).
4. An added test `test_fork_bomb_is_stopped` (LIMIT: pids) and `test_stdout_flood_is_capped`; the brief's limit list names pids but had no test for it.

Self-review findings

- Image digest is not reproducible across rebuilds (apt, pip sdist build of sexpdata, BuildKit metadata), so IMAGE_DIGEST changes whenever build.sh runs; committed value matches the image currently on this machine.
- The base image digest is 4 days old at build time (created 2026-11-05).
- The component repository is built from whatever KICAD_SYMBOL_DIR points at; nothing checks that it is 10.0.5's, nor that the run-time mount matches the build-time one. Default is the host KiCad.app path.
- `--mount source=$PROGRAM` breaks on a path containing a comma (none of ours do).
- The ready marker and the pids/ENOSPC classification can be imitated by a program (printing the marker, or exhausting pids then raising something else); this protects against runaways, not an adversary.
- run_emitter's 120 s release wait means a container whose emit.sh died lingers up to 2 minutes.
- emit.sh requires a host `python3` for cap_stream.py.

Concerns

- Sandbox environment: in this session `docker pull`/`build` hung on the macOS keychain credential helper (docker-credential-osxkeychain). I ran docker with DOCKER_CONFIG pointing at an empty scratch config and a PATH without /usr/local/bin's credential helpers (anonymous pulls of public images). The scripts contain no such shim; in a normal shell they need nothing extra. Several stale hung `docker-credential-osxkeychain get` / `docker manifest inspect` processes from my first attempts are still running (PIDs 24363, 24453, 24766, 24794); kill was refused by the permission classifier for one combined command, so they were left.

What changed
- Important 1: emit.sh has log_line (writes a newline first if the log's last byte is not one, then the line) and limit_line NAME. All three LIMIT lines and every emit.sh diagnostic go through it.
- M1: if `docker kill --signal USR1` fails, emit.sh removes page.kicad_sch, logs "emit.sh: the sheet was read out of <name> but SIGUSR1 could not be sent ...", and exits 1.
- M3: the status file and a group-pid file now sit in a `mktemp -d` dir. The brace group records its PID with `sh -c 'echo $PPID'`, because macOS /bin/bash is 3.2 and has no BASHPID. The EXIT trap kills the container, kills the group, runs `wait`, removes the container, then `rm -rf`s the dir.
- M4: pids_max_events() returns the counter, or None if pids.events is absent. main() reads it before the program runs. limit_name(exc, pids_before) blames pids only when the counter rose. If either reading is missing it prints "PIDS-CHECK: could not run: ...".
- M7: requirements.in now names lock.sh. lock.sh sets CUSTOM_COMPILE_COMMAND to the exact pip-compile command it runs. I regenerated the lock and only the header line changed; every pin and hash is identical. The old `--no-index` came from pip-tools' own reconstruction of the command line.
- M9: test_pin_fix_finds_pins_not_first_child places Connector_Generic:Conn_01x05 through emit.sh and asserts the instance carries pins {1..5}.
