## The interface you consume

export interface BoardRef {
  readonly name: string
  readonly circuit: string
  readonly export: string
}
export function boardRefs(repoRoot: string): readonly BoardRef[]

export interface BoardSheets {
  readonly board: string
  readonly outcome: "generated" | "refused" | "no-declaration"

## Change 1 — `GuideSchematic` gains two variants

In `tools/guide/guide.ts`:

```ts
export type GuideSchematic =
  | { readonly kind: "printed"; readonly path: string }
  | { readonly kind: "generated"; readonly path: string }
  | {
      readonly kind: "withheld"
      /** Repository-relative perfboard.json. */
      readonly declarationPath: string
      /** Repository-relative circuit module: what the pages WERE checked against. */
      readonly circuitPath: string
      /** Why it was withheld, in the words the gate used. Never empty. */
      readonly reason: string
    }
  | {
      readonly kind: "none"
      readonly declarationPath: string
      readonly circuitPath: string
    }
```

**`withheld` is a FOURTH variant and must not be collapsed into `none`.** `none` means *this board
declares no schematic*. `withheld` means *a schematic was generated and judged unfit to build from*.
Two different claims about two different situations. That file's own comment says the union exists
so an absence is "a shape this file has to handle rather than a field it can skip"; printing one
notice for both is the failure that comment names.

In the HTML builder:
- `generated` renders the schematic page exactly as `printed` does, plus one line saying the sheet
  was generated by `schgen` from the board's authoring declaration and is not hand-drawn.
- `withheld` renders a bordered notice, in the same style as the existing `none` notice, naming:
  the board; the declaration path; the circuit the other pages WERE checked against; the reason
  verbatim; and the command that reproduces it, `bun run tools/schgen/board-geometry.ts`.

## Change 2 — the packet's second schematic source, and the gate

In `writeGuidePacket` in `tools/guide/packet.ts`, where `schematic` is currently computed from
`declaration.schPath`:

- `schPath` present -> `{ kind: "printed", path: <repo-relative schPath> }`, unchanged.
- `schPath` absent -> resolve the board's name as `path.basename(declaration.dir)`, find its
  `BoardRef` with `boardRefs(repoRoot).find((r) => r.name === name)`, and call `boardSheets(ref,
  repoRoot, { outDir: <a temp dir you create>, pdf: false })`. Then:
  - no `BoardRef` found, or `outcome === "no-declaration"` -> `{ kind: "none", ... }`, which is
    today's behaviour for a board that genuinely has none.
  - `outcome === "refused"` -> `{ kind: "withheld", reason: <the blocker, in full> }`.
  - `outcome === "generated"` and `drawings` contains ANY `fieldFallbacks` ->
    `{ kind: "withheld", reason: "<n> fallback field placement(s): text the placer could not keep clear" }`.
  - `outcome === "generated"` with no fallbacks anywhere -> export the PDF from `schematicRoot` with
    `defaultExportSchematicPdf`, into the staging directory as `SCHEMATIC_PDF`, and return
    `{ kind: "generated", path: SCHEMATIC_PDF }`.

**THE GATE IS `drawings.every((d) => d.fieldFallbacks.length === 0)`.** A fallback field placement
IS text drawn over something — that is what the type means.

Remove the temp directory when you are done with it, including on the failure paths.

`packetFiles` is called with `hasSchematic = schematic.kind === "printed" || schematic.kind === "generated"`.

## Tests

Create `tests/guide/generated-schematic.test.ts`. No casts — `GuideInput` and `GuideSchematic` are
both exported, `GuideImages.clusters` is `string | undefined` and REQUIRED (supply it explicitly),
and `powerUpChecks`, `wiringPath` and `scaffold` are likewise required-and-explicitly-undefined.

```ts
import { describe, expect, it } from "bun:test"
import { buildGuideHtml, type GuideInput, type GuideSchematic } from "../../tools/guide/guide.ts"

const input = (schematic: GuideSchematic): GuideInput => ({
  boardName: "pultec-low-boost",
  generated: "2026-10-27",
  layoutPath: "boards/pultec-low-boost/pultec-low-boost.perfboard.vrt",
  schematic,
  images: { designators: "<svg/>", values: "<svg/>", copper: "<svg/>", clusters: undefined },
  checklist: [],
  powerUpChecks: undefined,
  wiringPath: undefined,
  scaffold: undefined,
})

describe("a withheld schematic is a different claim from an absent one", () => {
  it("names the reason, so nobody reads a withheld sheet as a board with no schematic", () => {
    const html = buildGuideHtml(
      input({
        kind: "withheld",
        declarationPath: "boards/pultec-low-boost/perfboard.json",
        circuitPath: "circuits/pultec/physical/low-boost.ts",
        reason: "5 fallback field placement(s): text the placer could not keep clear",
      }),
    )
    expect(html).toContain("5 fallback field placement")
    expect(html).toContain("withheld")
    expect(html).not.toContain("there is no schematic for pultec-low-boost to print")
  })

  it("a generated-and-clean schematic prints as a page, like a hand-authored one", () => {
    const html = buildGuideHtml(input({ kind: "generated", path: "schematic.pdf" }))
    expect(html).toContain("schematic.pdf")
    expect(html).not.toContain("withheld")
  })

  it("an absent schematic still prints the no-schematic notice, unchanged", () => {
    const html = buildGuideHtml(
      input({
        kind: "none",
        declarationPath: "boards/pultec-low-boost/perfboard.json",
        circuitPath: "circuits/pultec/physical/low-boost.ts",
      }),
    )
    expect(html).toContain("no schematic")
    expect(html).not.toContain("withheld")
  })
})
```
