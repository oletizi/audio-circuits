centring rule to all five Pultec section-board pages, re-rendered the five

3. The centring rule
--------------------

`scripts/center.py` shifts every absolute x in the sheet **body** by one offset
and never touches `lib_symbols`. **It is committed here because the rule all five
pages were centred by had existed only in a session scratchpad, which is
destroyed** - and a rule that cannot be re-run is a figure in prose.

**WHAT "CENTRED" MEANS HERE, stated because it is a choice.** The extent is the
min and max of the body's **anchor coordinates** - wire ends, symbol origins,
label and text positions, rectangle corners - not the extent of the rendered ink,
which reaches further by an amount living in `lib_symbols` and in font metrics.
That is the rule the page the reviewer approved was centred by, and all five are
centred by it so that no page is centred by a different definition from its
neighbours.

### 3.1 Four defects found by reading it, and what changed

1. **It used a `chr(1)` sentinel for the `lib_symbols` block without checking the
   source for one.** A source already containing that byte would have had it
   replaced by the whole symbol library. Now refused by name.
2. **Its `(start x y)(end x y)` pair regex was never checked for totality.** It
   matches the two only when **adjacent**, which is true of a `rectangle` and
   false of an `arc`, whose `(mid ...)` sits between them. On an arc the pattern
   matches nothing, all three points stay put, and the old script printed its
   margins and exited 0. It now counts the literal `(start ` and `(end ` tokens
   and refuses unless the pattern consumed every one. On these five sheets it
   consumed 4 to 6 pairs each and left none.
3. **Rigidity was checked by counting coordinates**, which a shifter that moved
   one coordinate by the wrong amount would pass. It now **re-reads the written
   file** and requires the sorted coordinate list to differ from the input's by
   exactly `dx` at every position, so the output formatter's rounding is inside
   the proof.
4. **A zero offset is now a result rather than a skip**: the file is still
   written and the output asserted **byte-identical** to the input.

### 3.2 The zero-offset guard was dead on arrival, and that is the most useful finding in this section

The guard in (4) was first written `if dx == 0`. **An already-centred sheet does
not give exactly zero** - `dx` is computed through a subtraction and a halving,
so the approved hi-cut page gives `-7.11e-15` and prints as `-0.0000`. Under
`dx == 0` the assertion was **dead on precisely the two sheets it exists to
protect**: the approved page, whose bytes must not move, and the mid page. It
passed both without comparing anything.

It now tests `abs(dx) <= 5e-5`, the same tolerance the rigidity proof uses, and
**`scripts/zero_offset_control.py` exercises it**: it hands `center.py` an
already-centred sheet with one body coordinate respelled `139.7` as `139.70` -
same number, different bytes - and requires it to refuse. It does.

**That control was itself wrong the first time**, and the way it was wrong is
worth keeping: it perturbed the first `(xy ...)` in the file, which was **inside
`lib_symbols`**. That block is held out of the substitution and restored
verbatim, so the bytes matched, the guard passed, and the control reported a
clean result having tested nothing. It now searches past the end of the
`lib_symbols` block and refuses if it finds no body coordinate there.

### 3.3 Proving the shift is total before trusting it

`scripts/coord_heads.py` enumerates every list head reachable in each sheet body
and classifies it as moved-by-one-of-the-three-forms or carrying no absolute page
x, refusing on anything else. It confirms that **`arc`, `circle`, `center`,
`mid`, `polyline` and `radius` occur only inside `lib_symbols`** on all five
sheets - so the three textual forms are total here. Its control requires the walk
to find heads unique to `lib_symbols`, since an empty body list would read as
"nothing unhandled".

It found exactly one unclassified head: **`(mirror x)`** on `pultec-low-boost`'s
potentiometer. The `x` is an **axis token**, not a coordinate - it names the
symbol's own axis to flip about - so it holds no absolute page x and must not
move; the symbol still translates rigidly because its position is the `(at ...)`
beside it. Classified by name so the next unclassified head is a real finding.

### 6.1 Geometric - `scripts/translation_proof.py`

Parses with `docs/research/lib/kicad_sheet.py` and nothing else;
`docs/research/lib/selftest.py` was run first and reported **10 controls, every
one moved or fired**.

| board | placed points | fields | wire length | offset, worst deviation |
| --- | --- | --- | --- | --- |
| `pultec-hi-boost` | 367 | 128 | 1181.100 mm | +9.5250, dx 2.5e-14, dy 0 |
| `pultec-hi-cut` | 281 | 104 | 974.090 mm | 0, dx 0, dy 0 |
| `pultec-low-boost` | 325 | 98 | 605.790 mm | -8.8900, dx 1.4e-14, dy 0 |
| `pultec-low-cut` | 308 | 100 | 873.760 mm | -8.2550, dx 2.5e-14, dy 0 |
| `pultec-mid` | 472 | 176 | 1678.940 mm | 0, dx 0, dy 0 |

"Placed points" is every wire end, symbol origin, junction, label, rectangle
corner, text **and every symbol field position**; all of them moved by the one
offset in x and by zero in y. Counts (wires, symbols, pin points, labels,
junctions, group rectangles, texts) and every field **angle** are identical on
every board.

The four controls, applied to the after-sheet of every pair:

| check | control | result |
| --- | --- | --- |
| counts | one wire deleted | counts differ on all five |
| wire length | one wire shortened 5 mm | total differs on all five |
| rigid translation | one symbol moved 1.27 mm diagonally | the single-offset test fails on all five |
| field angles | one field rotated 90 degrees | angles differ on all five |

**One defect in this script was caught by reading it rather than by running it,
and it is the kind that would have passed silently.** `kicad_sheet.labels()`
yields `(kind, text, x, y, angle, shape, node)` - **the coordinates are at index
2 and 3, not 1 and 2**. The first version indexed 1, which picks up the label's
**text**, and text compares equal between a sheet and its translation. That would
have made the label contribution to the translation proof the one component that
could not fail. (`Wire.length` and `Wire.pts` are also properties rather than
methods, and `pts` returns a flat 4-tuple; those raised `TypeError` and were
caught by running it.)

### 6.2 Electrical - `scripts/netcmp.ts`

Nothing here parses a netlist: `kicad-cli` produces it and
`lib/kicad/netlist.ts`'s `importNetlist` parses it. Compared as **sets**, four
ways - component fingerprint (designator, value, libpart, footprint), net
**names**, the pin-set **partition** with names ignored, and the
**name-to-pin-set mapping**, which neither of the other two alone implies.

| board | components | nets | names | partition | name→pins |
| --- | --- | --- | --- | --- | --- |
| `pultec-hi-boost` | 27 | 21 | identical | identical | identical |
| `pultec-hi-cut` | 21 | 15 | identical | identical | identical |
| `pultec-low-boost` | 19 | 15 | identical | identical | identical |
| `pultec-low-cut` | 20 | 15 | identical | identical | identical |
| `pultec-mid` | 39 | 29 | identical | identical | identical |

**The two traps the task named are both guarded.** Parenthesis depth is counted
outside quoted strings before every export, and a non-zero final depth or a
negative excursion refuses by name - because `kicad-cli sch export netlist`
**exits 0 on a paren-broken sheet** and writes empty `(components)` and `(nets)`,
and two empty netlists compare identical. A zero-component or zero-net import is
refused rather than compared.

**The control had to be rebuilt, and the reason is worth carrying.** The task
asked for a control that reports a difference when one pin is moved. The first
version moved the **first body symbol** 1.27 mm diagonally and the netlist came
back **identical** - which looked like a blind comparator and was not. The first
body symbol on every one of these five sheets is **`#FLG01`, a `PWR_FLAG` that is
already floating**: its pin touches nothing, so KiCad exports it as its own
`unconnected-(#FLG01-...)` net both before and after, and the comparison was
correctly reporting no change to an inert perturbation.

**A control has to perturb something that is actually connected, and which
symbols those are is a property of each sheet.** So it now walks the body symbols
in order, stops at the first whose movement changes the netlist, and **names
it**; it refuses only if no symbol on the sheet produces a difference. On all
five, `#FLG01` is inert and **`#PWR01` is the symbol that discriminates**.

  rule, and changing the rule would have moved his approved page.
- **Nothing was withheld and nothing was stopped on.** No electrical fault was
  found on any of the five pages, and no page is being held back for any other
  reason.

virtual environment at `<scratchpad>/venv` (numpy 2.5.4, pillow 13.0.0); the

`python3 -m venv <dir> && <dir>/bin/pip install numpy pillow`. The TypeScript
scripts run under `bun`. `kicad-cli` is
`/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli`, KiCad E.D.A. 10.0.5.

```

  scripts/coord_heads.py            every body head, so the shift is proved total

  scripts/translation_proof.py      the geometric rigid-translation proof
```
